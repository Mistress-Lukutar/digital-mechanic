# Digital Mechanic — ИИ-агент для диагностики ДВС

Проект хакатона «ИИкузница / НейроДВС»: механик выбирает машину из парка,
запускает акустическую проверку, ИИ-агент объясняет результат по заводским
руководствам (RAG, с цитатами `[doc_id, стр. N]` и панелью документа) и
оформляет заявку на дефектовку в систему ТОиР.

**Стек:** FastAPI + агентный цикл на tool calling (OpenAI / Anthropic / Gemini,
SSE-стриминг шагов агента) · Vue 3 + TypeScript (тёмная тема) · SQLite ·
комплектные mock-интеграции ML-диагностики и ТОиР.

Все данные в системе синтетические; на экране входа требуется отметить
согласие на обработку данных (152-ФЗ).

---

## Что умеет система

### Для механика

- **Гараж и парк.** Карточки всех 50 ТС с моделью двигателя, типом топлива и
  статусом последней проверки; сводка «Главный механик» по всему парку;
  график динамики `anomaly_score` по истории проверок машины.
- **Чат с агентом.** Механик спрашивает по-русски («какой момент затяжки
  крышек коренных подшипников?», «что с машиной?») — агент сам вызывает
  нужные инструменты: диагностику, поиск по руководствам, карточку ТС.
  Ход рассуждений и вызовы инструментов видны в чате живым стримом (SSE).
- **Голос и фото.** Вопрос можно надиктировать микрофоном или приложить
  фото узла прямо в чат — изображение уходит в мультимодальную модель
  вместе с текстом вопроса.
- **Редактирование и ветвление.** Своё сообщение можно поправить — агент
  перегенерирует ответ в новой ветке, между ветками переключаются прямо
  на сообщении; при возврате в чат машины последний диалог открывается сам.
- **Ответы с источниками, а не «из головы».** Каждый технический факт
  сопровождается цитатой `[обозначение документа, стр. N]`; по клику страница
  руководства открывается во встроенном PDF-просмотрщике рядом с чатом.
- **Честный отказ вместо выдумки.** Если в руководствах этого двигателя ответа
  нет, агент прямо говорит об этом и рекомендует дефектовку — нормативы с
  чужих двигателей не переносятся никогда (это правило зашито в системный
  промпт и проверяется тестами).
- **Заявка на дефектовку одной кнопкой.** Агент собирает черновик: диагноз,
  приоритет с обоснованием, работы, запчасти и ссылки на страницы руководств.
  Механик проверяет черновик и подаёт заявку в ТОиР — система не отправляет
  ничего без подтверждения человека.
- **Строгая логика по качеству записи.** При непригодной записи
  (`check_failed`, `signal_quality: bad`) агент не ставит диагнозов вообще и
  ведёт механика к повторной записи; при пониженной надёжности сигнала —
  честно предупреждает, а не замалчивает.
- **История чатов** по каждой машине, мобильная адаптивность, интерфейс на
  четырёх языках (RU / UZ / KK / HI).

### Для администратора

- Дашборд экономики: число запросов, токены и стоимость по каждому диалогу,
  пересчёт на парк с редактируемыми допущениями и CSV-экспортом.
- Оповещения о нештатных ситуациях: несовместимость кода неисправности с
  карточкой ТС, подача заявки при сомнительной записи, сообщения агента —
  с бейджем непрочитанных и отметкой прочтения.
- Раскрытие любого диалога: пошаговый трейс агента (инструменты, аргументы,
  результаты) и цитаты из руководств.
- Управление пользователями (роли механик/админ) без правки конфигов.
- Настройки LLM (провайдер, модель, ключ) прямо в UI — смена модели не
  требует перезапуска и правки файлов.

### Инженерная часть

- **Мульти-провайдер LLM.** Один агентный цикл работает с любой
  OpenAI-совместимой локальной моделью (vLLM, llama.cpp, Ollama), а также с
  Anthropic и Gemini — провайдер переключается конфигурацией.
- **RAG-сервис по заводским руководствам** (модуль участника B,
  [rag/README.md](rag/README.md)): гибридный поиск BM25 + bge-m3 со слиянием
  RRF, фильтрация по двигателю до скоринга, уровни доверия `high/med/low` и
  честный сигнал `no_instruction`. hit@5 = 0.87 на ручном наборе вопросов —
  число воспроизведено свежей сборкой из текущего кода (сборка только на
  BM25 того же индекса даёт 0.72), refusal rate = 1.0 на вопросах вне базы.
  Каждый манифест индекса несёт провенанс сборки (модель эмбеддингов,
  версии библиотек, режим layout, коммит), поэтому метрика проверяется
  воспроизводимой сборкой, а не цитируется по старой. Сервис отделён по
  HTTP-контракту (`shared/models.py`), поэтому бэкенд переключается с
  встроенной заглушки на боевой поиск без изменения кода.
- **Устойчивость к деградации.** Без LLM работают диагностика, парк и заявки;
  без PDF-мануалов поиск честно отвечает «инструкции недоступны», остальной
  сценарий не ломается.
- **Качество под контролем.** 236 unit/integration-тестов бэкенда, 47 тестов
  RAG на синтетических PDF, e2e-сьют на Playwright (вход, все страницы,
  админка, контроль JS-ошибок и ответов 4xx/5xx после каждого теста), ruff и
  строгий `vue-tsc`. Оценка поиска — воспроизводимый гейт
  `python -m rag.eval --set all`.

## Запуск за 5 минут

### 0. Что нужно

- Python **3.11+**
- Node.js **18+** (сборка фронтенда)
- Доступ к любой LLM: локальной OpenAI-совместимой (vLLM, llama.cpp, Ollama…)
  или облачной (Anthropic / Gemini тоже поддерживаются)

### 1. Клонировать и установить

```bash
git clone https://github.com/Mistress-Lukutar/digital-mechanic
cd digital-mechanic

python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"     # Windows
# .venv/bin/pip install -e ".[dev]"       # Linux/macOS

cd frontend && npm install && cd ..
```

### 2. Настроить .env

```bash
copy .env.example .env     # Windows
cp .env.example .env       # Linux/macOS
```

Минимум, который стоит вписать, — параметры LLM:

```
LLM_PROTOCOL=openai_compatible
LLM_BASE_URL=http://<хост>:<порт>/v1
LLM_API_KEY=sk-...
LLM_MODEL=<имя модели>
```

URL заглушек (8001/8002), RAG (8003) и каталог мануалов уже предзаполнены.

Для поиска по руководствам впишите в `.env` ссылку на общее хранилище
(`MANUALS_DOWNLOAD_URL`; сама ссылка в git не попадает) — иначе см. шаг 3.

### 3. Докачать ресурсы и собрать индекс (одной командой)

```bat
scripts\bootstrap.bat      :: Windows
scripts/bootstrap.sh       :: Linux/macOS
```

Скрипт скачает issued-руководства (и DOCX кейса, если нужны) из общего
хранилища, распознает их, построит индекс с эмбеддингами и закэширует
всё вне git (документы — в `MANUALS_DIR`, индекс — в гитигнорируемом
`data/rag/`). Повторный запуск — cache-hit; `--no-embed` — BM25-only
без загрузки модели (~2.3 ГБ). Без этого шага агент честно отвечает
«инструкции недоступны», остальное работает.

### 4. Запустить одной командой

```bat
scripts\start.bat     :: Windows
scripts/start.sh      :: Linux/macOS
```

Скрипт при первом запуске сам соберёт фронтенд в `static/dist`, поднимет
заглушки ML (:8001) и ТОиР (:8002) и запустит API вместе с UI на
**http://localhost:8011** (проверка живости: `/health`).

### 5. Войти

- При пустой базе на старте создаётся администратор, пароль печатается
  **в консоль API-процесса** (или задайте `ADMIN_INITIAL_PASSWORD` в `.env` —
  тогда ничего не печатается); после первого входа обязательна смена пароля.
- **Админ:** дашборд экономики (usage, стоимость запросов), управление
  пользователями, настройки LLM (провайдер/модель/ключ) прямо в UI.
- Создайте через админку пользователя-механика и работайте под ним:
  гараж → чат с агентом → заявка. Механику также доступны график
  `anomaly_score` и сводка «Главный механик» по всему парку.

Без доступной LLM чат не отвечает, но диагностика, парк и заявки работают.

## Голосовой ввод с телефона (iOS/Safari): включите HTTPS

Кнопка микрофона в чате использует Web Speech API браузера. Safari
распознаёт речь **только в защищённом контексте (HTTPS)**: если открыть
стенд с телефона как `http://<IP-компьютера>:8011`, доступ к микрофону
даже не будет запрошен — кнопка молча не сработает (в Chrome/Android
локальная сеть прощается, для iOS нужен этот шаг).

1. Сгенерируйте самоподписанный сертификат, указав IP компьютера в
   локальной сети (можно несколько `--host`):

```bat
.venv\Scripts\python.exe scripts\generate_cert.py --host 192.168.1.42   :: Windows
.venv/bin/python scripts/generate_cert.py --host 192.168.1.42           # Linux/macOS
```

   Сертификат и ключ появятся в гитигнорируемом `certs/`.

2. Запустите стенд с переменными окружения `SSL_CERTFILE`/`SSL_KEYFILE`
   — скрипт сам переключится на `https://localhost:8011`:

```bat
set SSL_CERTFILE=certs\dev-cert.pem
set SSL_KEYFILE=certs\dev-key.pem
scripts\start.bat
```

```bash
SSL_CERTFILE=certs/dev-cert.pem SSL_KEYFILE=certs/dev-key.pem scripts/start.sh
```

3. На телефоне откройте `https://<IP-компьютера>:8011/`. Safari покажет
   предупреждение о самоподписанном сертификате — «Показать подробности»
   → «Перейти на сайт»; затем при первом нажатии микрофона разрешите
   доступ. Если микрофон по-прежнему недоступен, проверьте «Настройки →
   Safari → Микрофон» на iPhone.

## Как это работает внутри

```
Механик ──► Vue 3 SPA ──► FastAPI ──► Агентный цикл (tool calling)
                              │            ├── get_diagnostic_result ─► Mock ML (:8001)
                              │            ├── search_manuals ────────► RAG-сервис (:8003)
                              │            ├── get_vehicle_info ──────► SQLite / vehicles.json
                              │            ├── create_ticket ─────────► черновик в UI
                              │            └── show_document ─────────► PDF-панель
                              └── Подача заявки (кнопкой) ──► Mock ТОиР (:8002)
```

Агент работает по системному промпту с жёсткими правилами
([prompts/system.md](prompts/system.md)): обязательное цитирование, уровни
доверия поиска, протоколы для каждого тестового сценария ТЗ (плохая запись,
низкая уверенность, отсутствие инструкции, вопрос вне базы), запрет на
смешивание данных разных двигателей.

## Руководства (авторские права)

Заводские PDF **не входят в репозиторий** (copyright). При развёртывании
одна команда докачивает документы из общего хранилища, распознаёт
руководства, строит поисковый индекс с эмбеддингами и кэширует всё это
вне git (документы — в `MANUALS_DIR`, индекс — в гитигнорируемом
`data/rag/`); повторный запуск — дешёвый cache-hit:

```bash
scripts\bootstrap.bat            # Windows
scripts/bootstrap.sh             # Linux/macOS
```

Ссылка на общее хранилище лежит в гитигнорируемом `.env` (переменная
`MANUALS_DOWNLOAD_URL`; сама ссылка в git не попадает — это проверяет
guard-тест). Ручной вариант: положить шесть issued-руководств в каталог
`MANUALS_DIR` (по умолчанию `data/manuals/`, но лучше внешний каталог —
переменная в `.env`) и выполнить `python -m rag.setup --from <каталог>`.

Наборы вопросов для оценки поиска и ручной блок системного промпта тоже
цитируют руководства — они распространяются одним защищённым архивом:

```bash
pip install pyzipper            # разово, для чтения AES-архива
scripts\fetch_external.bat      # Windows
scripts/fetch_external.sh       # Linux/macOS
```

Ссылка и пароль архива — в гитигнорируемом `.env` (`EXTERNAL_CONTENT_URL`,
`EXTERNAL_CONTENT_PASSWORD`); распаковка идёт в `RAG_EVAL_DIR` и каталог
`PROMPT_MANUAL_FILE` вне репозитория. Без архива агент работает на базовом
промпте, а оценка поиска предупреждает об отсутствии наборов.

Без мануалов `search_manuals` честно отвечает «инструкции недоступны»
(тест-кейс «нет инструкции»), остальной сценарий полностью работает.
Подробности: [data/manuals/README.md](data/manuals/README.md).

## Режим разработки

`scripts\dev.bat` / `scripts/dev.sh` — то же, но API на **:8000** с
автоперезагрузкой и фронтенд в vite dev-сервере на **http://localhost:5173**
(прокси `/api` → 8000). Открывать именно `localhost` — vite слушает IPv6.

Ручной вариант (четыре терминала из корня):

```bash
# Заглушки (MOCK_DATA_PATH — абсолютный путь к файлу парка)
MOCK_DATA_PATH=<абс>/data/vehicles.json \
  .venv/Scripts/python.exe -m uvicorn mock_ml.app:app --port 8001 --app-dir vendor
MOCK_DATA_PATH=<абс>/data/vehicles.json \
  .venv/Scripts/python.exe -m uvicorn mock_toir.app:app --port 8002 --app-dir vendor

# API
.venv/Scripts/python.exe -m uvicorn mechanic.main:app --port 8000

# Фронтенд (прокси /api → 8000)
cd frontend && npm run dev
```

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `src/mechanic/` | FastAPI-бэкенд: агентный цикл, инструменты агента, сервисы, API |
| `shared/` | Контрактные Pydantic-модели (общие с RAG-модулем участника B) |
| `frontend/` | Vue 3 + TypeScript SPA: гараж, SSE-чат с карточками, история чатов, встроенный PDF-просмотрщик, заявки, админка |
| `rag/` | RAG-сервис поиска по руководствам: инжест PDF, гибридный индекс, эвал-гейты |
| `data/` | Комплектные синтетические данные: `vehicles.json`, `fault_types.json`; `manuals/` — манифест документов (PDF поставляются отдельно); eval-наборы вопросов — внешние, каталог задаётся `RAG_EVAL_DIR` (см. [rag/README.md](rag/README.md)) |
| `vendor/` | Комплектные заглушки: Mock ML (`POST /diagnose`), Mock ТОиР (`POST /tickets`), OpenAPI-спеки |
| `prompts/` | Системный промпт агента (`{vehicle_block}` / `{docs_block}`); ручной блок руководств вставляется в рантайме из `PROMPT_MANUAL_FILE` |
| `tests/` | pytest-набор бэкенда |
| `e2e/` | Playwright UI/UX-смоук: вход, навигация по всем страницам, админка, контроль ошибок консоли/сети |

## Проверки

```bash
.venv/Scripts/python.exe -m pytest tests -q
.venv/Scripts/python.exe -m ruff check src shared tests
cd frontend && npm run build    # vue-tsc strict + vite build
```

UI/UX-смоук (требует `pip install -e ".[e2e]"`; браузер — системный Edge/Chrome,
без скачивания Playwright-браузеров; стенд — свои моки + API на случайных
портах под `/mech/`, как за обратным прокси):

```bash
.venv/Scripts/python.exe -m pytest e2e -v
```

Сьюит после каждого теста проверяет, что на странице не было JS-ошибок,
ошибок консоли и ответов 4xx/5xx (кроме ожидаемых 401 на `auth/login`/`auth/me`
— семантика «не авторизован»).
