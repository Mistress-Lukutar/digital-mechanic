# Руководства по двигателям — не распространяются с репозиторием

Заводские руководства по ремонту и эксплуатации являются объектами авторского права, поэтому **PDF-файлы и любой текст, извлечённый из них, не включены в этот репозиторий** (и никогда не должны попадать в его историю). При развёртывании они скачиваются и обрабатываются **вне git**: документы попадают в `MANUALS_DIR` (внешний каталог по конфигурации), извлечённый текст и поисковый индекс кэшируются в гитигнорируемом `RAG_DATA_DIR` (по умолчанию `data/rag/`).

## Развёртывание одной командой (рекомендуется)

Одна команда делает всё — докачивает недостающее, распознаёт руководства, строит индекс с эмбеддингами и кэширует его:

    scripts\bootstrap.bat            # Windows
    scripts/bootstrap.sh             # Linux/macOS
    python scripts/bootstrap.py      # напрямую

Ссылка на общее хранилище берётся из гитигнорируемого `.env` (сама ссылка не должна попадать в коммиты — это проверяет guard-тест):

    MANUALS_DOWNLOAD_URL=https://...   # ваш .env, не .env.example

Bootstrap идемпотентен: уже скачанные файлы пропускаются по размеру, а построенный индекс переиспользуется вместо пересборки (`--force-index` пересобирает; `--no-embed` собирает BM25-only индекс без загрузки модели ~2.3 ГБ).

## Ручной вариант

Без общей ссылки получите шесть выпущенных руководств из материалов хакатона и поместите их (оригинальные имена допустимы — `rag.setup` распознаёт задокументированные алиасы) в каталог, на который указывает `MANUALS_DIR`, затем запустите тот же bootstrap. Ожидаемые имена файлов по `manifest.json`:

| doc_id (раздел 3 спецификации) | Ожидаемое имя файла | Двигатели |
|---|---|---|
| `236-3902150-Б РЭ` | `yamz-236_re_2010.pdf` | ЯМЗ-236М2 |
| `236.01.01 РК` | `yamz-236_rk_2014.pdf` | ЯМЗ-236М2 |
| `536.3902150 РЭ` | `yamz-536_re_2016.pdf` | ЯМЗ-536 |
| `536.01.02 РК` | `yamz-536_rk_2013.pdf` | ЯМЗ-536 |
| `ЗМЗ-5234.10 РК` | `zmz-5234_rk_2025.pdf` | ЗМЗ-5234.10 |
| `ЗМЗ-409 РЭТОиР` | `zmz-40904-40905_rk_2025.pdf` | ЗМЗ-40904.10, ЗМЗ-40905.10 |

По умолчанию `MANUALS_DIR=data/manuals` внутри дерева репозитория; каталог гитигнорируется для PDF и DOCX, но **внешний** каталог через переменную `MANUALS_DIR` в `.env` держит даже локальные копии вне дерева репозитория и является рекомендуемой настройкой — внешняя база знаний подключается через конфигурацию, а не коммитится в Git.

При отсутствии руководств приложение продолжает работать: диагностика, виды парка и работа с заявками функционируют; панель документов и поиск по руководствам выдают явный ответ «файлы руководств недоступны» вместо вымышленного контента.
