# Модуль RAG (участник B) — поиск по руководствам для Цифрового механика

Самостоятельный сервис на FastAPI, который превращает шесть выпущенных руководств по двигателям в службу поиска для агента: `POST /search` со строгой фильтрацией по модели двигателя и честным сигналом «нет инструкции», плюс получение страниц. Контракты описаны в `shared/models.py` (`SearchHit`, `SearchResponse`,
`PageContent`) — бэкенд (участник A) вызывает этот сервис по HTTP через переменную окружения `RAG_API_URL` и не требует изменений кода для переключения с заглушки.

**Авторские права:** PDF-файлы руководств не являются частью этого репозитория и никогда не должны попадать в него (ни файлы, ни извлечённый текст, ни индексы). Всё, что построено на основе PDF, попадает в gitignored `data/rag/`; это контролируется тестами (`rag/tests/test_guard.py`).

## Установка одной командой

При развёртывании всё делает одна идемпотентная команда — докачивает недостающее по ссылке на общее хранилище (`MANUALS_DOWNLOAD_URL` в гитигнорируемом `.env`; сама ссылка не коммитится), распознаёт руководства, строит индекс с эмбеддингами и кэширует его:

```bash
scripts/bootstrap.sh                # Linux/macOS
scripts\bootstrap.bat               # Windows
# python scripts/bootstrap.py --no-embed   # только BM25 (без модели ~2,3 ГБ)
```

Уже скачанные файлы пропускаются по размеру; построенный индекс в `RAG_DATA_DIR` (по умолчанию `data/rag/`, gitignored) переиспользуется — повторные развёртывания дают cache-hit (`--force-index` пересобирает).

Под капотом bootstrap запускает `rag.setup`, который можно использовать и напрямую, когда PDF уже есть на диске (любые имена файлов — два файла с русскими названиями из пакета хакатона тоже распознаются):

```bash
python -m rag.setup --from "C:\\path\\to\\pdfs"
```

Команда распознаёт каждое руководство (имя файла из manifest → документированное обозначение → количество страниц + отпечаток обложки), помещает его под именем файла из manifest в `MANUALS_DIR` (по умолчанию `data/manuals`, общее с бэкендом, чтобы панель документов могла отдавать PDF), строит индекс поиска и выводит сводку. Опции: `--link` жёсткая ссылка вместо копирования, `--no-embed` только BM25 без загрузки модели встраиваний (~2,3 ГБ), `--skip-ingest` только размещение файлов, `--eval` прогон `python -m rag.eval --set all` сразу после сборки (нужен `RAG_EVAL_DIR`, код выхода eval возвращается как код выхода команды — см. «Воспроизводимость» ниже).

Ручные шаги, если предпочитаете:

```bash
# файлы уже в MANUALS_DIR с именами из manifest
python -m rag.ingest                 # построение индекса (BM25 + встраивания)
python -m rag.ingest --no-embed      # только BM25
uvicorn rag.service:app --port 8003  # запуск сервиса (RAG_API_URL в .env бэкенда)
python -m rag.eval --set all         # гейт качества перед каждым коммитом этапа
```

Зависимости: `pip install -r rag/requirements.txt` (PyMuPDF, numpy/scipy,
PyStemmer, PyYAML; sentence-transformers для dense-части). fastapi,
uvicorn, pydantic, httpx и pytest идут из корня проекта — не редактируйте root `pyproject.toml` (участник A владеет им).

## Контракт сервиса (неизменный, issue #1)

- `POST /search` `{query, engine_model, top_k=5}` →
  `{"results": [{doc_id, doc_title, page_pdf, section, text, score, tier}],
  "no_instruction"}`. Фильтрация по двигателю происходит ДО скоринга; ничего выше порога → `{"results": [], "no_instruction": true}`.
- `GET /document/{doc_id}/page/{page_pdf}` → `PageContent` (текст страницы + локальный `pdf_path`, может быть null).
- `GET /health` → версия индекса, режим (`hybrid` | `bm25`), статистика по документам.
- Значения `doc_id` — обозначения из manifest («236.01.01 РК»), цитируются дословно в чате и хранятся в заявках; страницы — PDF-страницы, отсчёт с 1.

Дополнительные поля расширения `fault_code` и `doc_id` принимаются, но никогда не являются обязательными — текущий клиент бэкенда их не отправляет.

## Как это работает

```
PDFs ──► rag/ingest.py ──► data/rag/index/vNNN/  +  rag/knowledge/*.yaml
           извлечение: определение порядка чтения координат (исправляет
           перемешанные таблицы 236 RE), линейные таблицы → markdown,
           нормализация дефисов/мягких дефисов/диапазонов, склейка по
           корпусному словарю для разорванных слов
           («по дшипнико в»), удаление бегущих заголовков, парсинг
           печатного оглавления с определением смещения, реестр модулей
           для 536 RK
           чанки: ограничены страницами, ≤700 символов, не пересекают страницу
           индекс:  BM25 (формула Lucene, scipy CSR) + встраивания bge-m3
                   с кэшем по хешу текста; слияние RRF
           поиск: маска двигателя перед скорингом → расширение запроса (коды
                   неисправностей F01–F14, сленг механиков) → BM25 ∥ dense → RRF →
                   tier (high/med/low относительно сравнимого балла) → честный
                   no_instruction (ячейки покрытия verified-none, пустые результаты)
```

Словари знаний находятся в `rag/knowledge/*.yaml` (версионируются вместе с кодом): паспорт документа с отпечатками и подсказками оглавления, коды неисправностей, синонимы сленга и матрица покрытия двигатель × неисправность, ячейки `none` которой определяют поведение отказа, проверяемое жюри.

## Конфигурация (переменные окружения / .env)

| Переменная | По умолчанию | Значение |
|---|---|---|
| `MANUALS_DIR` | `data/manuals` | manifest + PDF-файлы (общие с бэкендом) |
| `RAG_DATA_DIR` | `data/rag` | построенные артефакты (gitignored) |
| `RAG_EVAL_DIR` | `data/eval` | внешние наборы вопросов — не коммитятся, укажите каталог вне репозитория |
| `RAG_EMBED_MODEL` | `BAAI/bge-m3` | `none` отключает dense-часть |
| `RAG_DEVICE` | `auto` | `cpu` или `cuda` |
| `RAG_TIER_HIGH` / `RAG_TIER_MED` | `0.70` / `0.55` | пороги tier |
| `RAG_INDEX_VERSION` | latest | привязка к конкретной версии |

Без модели встраиваний сервис деградирует до BM25 (`/health` показывает
`mode: bm25`); без построенного индекса отвечает 503 с подсказкой.

## Тесты и гейты качества

```bash
pytest rag/tests   # 41 тест на синтетических PDF (реальные руководства не нужны)
pytest             # бэкенд-набор остаётся зелёным (файлы участника A не тронуты)
ruff check rag
python -m rag.eval --set all   # hit@1/hit@5 (+1 страница), MRR, доля отказов
```

Наборы eval живут **вне репозитория** (задайте `RAG_EVAL_DIR`, например соседний каталог `../rag-eval`; описание состава — в его README): золотые значения проверены по рендерам изображений страниц, вопросы поиска по разделам с золотыми страницами и вопросы с обязательным отказом для проверенных ячеек «нет инструкции». Рядом лежит набор `overrefusal.jsonl` (issue #15): вопросы на **покрытых** ячейках — сленг механиков, парафразы без лексического совпадения с руководством и стилистические двойники negative-кейсов; отказ на них — измеряемый over-refusal (цель 0.0, кейс падает и по отказу, и по промаху золотой страницы ±1). Набор передан владельцу репозитория для следующего обновления внешнего архива (`EXTERNAL_CONTENT`), вместе с расширенным до 16 кейсов `negative.jsonl`. `golden.jsonl` цитирует точные значения из руководств, поэтому наборы не коммитятся — та же политика, что и для самих PDF. Запуск: `RAG_EVAL_DIR=../rag-eval python -m rag.eval --set all`. Наборы и промпт-блок распространяются одним AES-архивом: `scripts/fetch_external.py` скачает и распакует его в `RAG_EVAL_DIR` и каталог `PROMPT_MANUAL_FILE` (ссылка и пароль — в gitignored `.env`: `EXTERNAL_CONTENT_URL`, `EXTERNAL_CONTENT_PASSWORD`; нужен `pip install pyzipper`).

## Воспроизводимость флагманского индекса (issue #14, H2)

Руководства приходят по ссылке (`MANUALS_DOWNLOAD_URL` в `.env`), eval-наборы —
из защищённого архива (`fetch_external.py` → `RAG_EVAL_DIR`), а индекс строится
локально в гитигнорируемый `data/rag/` — ничего защищённого в git не попадает.
Поэтому флагманская метрика обязана воспроизводиться из текущего кода: свежая
загрузка плюс описанная сборка должны давать лучший индекс. Путь из трёх команд:

```bash
python scripts/fetch_manuals.py                    # 1. PDF/DOCX по ссылке из .env
python -m rag.setup --from data/manuals --eval     # 2. распознать, построить индекс, сразу eval
#                                                  (--eval прогоняет python -m rag.eval --set all
#                                                   и возвращает его код выхода; нужен RAG_EVAL_DIR)
# 3. то же одной командой: scripts/bootstrap.bat / scripts/bootstrap.sh
```

Факты сборки фиксируются в манифесте версии (`data/rag/index/vNNN/manifest.json`,
ключ `provenance`): модель эмбеддингов, версии библиотек (pymupdf / numpy /
sentence-transformers), режим layout (классический детектор таблиц против
нейросетевого), git-коммит кода, из которого собран индекс. Диапазоны версий в
`rag/requirements.txt` сжаты так, чтобы сборка воспроизводилась; точные версии
каждой сборки видны в её манифесте. Векторный кэш (`data/rag/emb_cache/`) ключуется
по sha256 текста чанка — пересборка после правок словарей пере-эмбеддирует только
новые чанки.

Текущие числа (индекс **v012**, собран текущим кодом ветки решения issue #14 (H1+H2)
и плана fix-golden-value-checks — `values_ok` 7→10; классический детектор таблиц —
`pymupdf._layout_enabled = False`, см. `rag/ingest.py`;
встроенный нейросетевой layout запускает ~64 ONNX-потока на страницу и находит
меньше таблиц на этих руководствах; `python -m rag.eval --set all`, `RAG_EVAL_DIR=../rag-eval`):

| набор | кейсов | hit@1 | hit@5 | MRR | примечание |
|---|---|---|---|---|---|
| manual | 46 | 0.478 | **0.870** | 0.632 | цель ≥ 0.85 |
| golden | 10 | 0.800 | **1.0** | 0.883 | значения подтверждены **10/10** |
| negative | 16 | — | — | — | доля отказов **1.0** (12 ячеек `none` + поверхностные стили) |
| overrefusal | 18 | 0.722 | **1.0** | 0.803 | доля отказов **0.0** — covered-клетка обязана отвечать (issue #15) |

Гибридный (bge-m3 + RRF поверх BM25). Сборка только на BM25 того же индекса даёт
manual hit@5 0.717 (независимо воспроизведено участником A; перепроверено на v011 —
без изменений); dense-часть добавляет примерно +0,15. Числа выше получены свежей
сборкой из текущего кода (воспроизведено, больше не цитируется по старой сборке):
после слияния comparable-скора per-chunk (issue #14 H1) hit@5 остался на базовом
уровне 0.870, refusal — 1.0; comparable-first упорядочивание оценивалось на этих же
наборах и отклонено (поднимает hit@1/MRR, роняет manual hit@5 до 0.826).

Раунд fix-golden-value-checks (golden `values_ok` 7→10, hit@5 0.800→1.0):
перевернутые страницы 236 РЭ (6–11, 13, 14) читаются в координатах читателя —
сводная spec-таблица стр. 6–9 извлекается в правильном порядке слов и строк
(инвертированная `derotation_matrix` → `rotation_matrix`); моментные запросы
(«затягиваются болты…») получают формулировку «момент затяжки» приложений-таблиц;
детект «прогиб ремня привода генератора» ведёт на F04, а не F05 (vocabulary gap
закрыт связкой «прогиб → натяжение ремня» в словаре); швы чанкинга не рвут слова.
Gold-набор: g04 получил вторую валидную страницу (стр. 19, тот же норматив в прозе
«Контроль за работой») — обновление передаётся во внешний архив вместе с набором.
Диверсификация top-k по страничным кластерам (п.5 плана) оценена и отклонена:
cap 2 чанка на окно ±2 страницы роняет golden hit@5 1.0→0.9 и `values_ok` 10→9 —
золотые страницы нормативных таблиц живут в собственных окнах-соседях.
